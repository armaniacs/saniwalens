ドキュメント

設計意図は docs/specs/ にあり、このページは操作方法の案内です。 初回は上から順に読み、2 回目以降は表とリンク集を引いてください。 英語版は こちら。

パイプライン

一度 analyze して何度も読む ― 分析結果のデータベース（ストア）が段階をつなぐ
コマンド すること
saniwalens tui 対話で harness → 見るもの → 範囲の順に聞いて回します。初回はここから。引数なしの saniwalens でも同じです。
saniwalens doctor 健康診断。全体／プロジェクト別に表示。
saniwalens analyze transcript（対話履歴）と設定をストアに展開（変わった分だけ追加）。読み取りコマンドの実行時に自動で走ります。
saniwalens sql '<query>' ストアへの読み取り専用 SQL なら何でも書けます。分析の中心はストアです。
saniwalens optimize 所見をもとに改善案を作ります。advisor（相談相手のセッション）と対話しながら進めます。
saniwalens cleanup 保存した --apply 計画と backup の一覧・掃除。ストアは要らない。

定番の切り口（ビュー）

定番の見方が要るときは、SQL を書く前にここを見ます。 単なるクエリでは書けない分類・提案をまとめた切り口です。 使う範囲は --scope global | project | project:<slug> で絞ります。

spec 対応表

仕様本文は英語です。下はこのサイト内の spec ページへの対応表で、各ページの末尾から GitHub の原文にも飛べます。

  • architecture.md ― SQLite を挟んだ二段階。カタログ × 利用の結合
  • cli.md ― コマンド契約と報告モデル（生成済み CLI リファレンスも参照）
  • surfaces.md ― 設定 surface のカタログ
  • events.md ― 利用イベントの spine
  • storage.md ― ストアの schema と移行
  • harness.md ― harness 別の契約
  • session-format*.md ― harness 別の transcript 形式
  • config-format*.md ― harness 別の設定形式

はまる前の注意

  • レポートに出る件数やトークン数は、どれから直すかの順位付けのための目安であり、課金の請求額ではありません。
  • ストア（分析結果をためる SQLite データベース）は、元の transcript が Claude Code 側で刈られても残ります。このファイルを消すと履歴は戻ってきません。一時的なキャッシュではないので、容量目的で消さないでください。
  • schema 変更時は自動でその場で移行されるので、消して作り直す必要はありません。
  • 一覧表は英語のまま。--language en|ja が切り替えるのは advisor への指示文だけです。
