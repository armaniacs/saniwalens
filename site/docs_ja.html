ドキュメント

設計意図は docs/specs/ にあり、この頁は動かし方への地図です。 英語版は こちら。

パイプライン

一度 analyze して何度も読む — ストアが段階をつなぐ
コマンド すること
saniwalens doctor 健康診断。全体 / プロジェクト別に分ける — まずここ。
saniwalens analyze transcript + 設定をストアに展開（増分）。読み取りは自動で走る。
saniwalens sql '<query>' ストアへの任意の読み取り専用 SQL。ストアこそ本体。
saniwalens optimize 所見を advisor セッションに渡して動かす。
saniwalens cleanup 保存した --apply 計画と backup の一覧・掃除。ストアは要らない。

ビュー

素のクエリにできない一手間（分類・アルゴリズム・提案）を持った切り口です。 範囲は --scope global | project | project:<slug>。

はまる前の注意

  • 数値は順位付け用の利用シグナルであり、課金台帳ではありません。
  • ストアは transcript より長生きします — 消すのはキャッシュ破棄ではなく本当の損失です。
  • schema 変更時はその場で移行するので、消して作り直す必要はありません。
  • 表本体は英語のまま。--language en|ja が切り替えるのは advisor の促し文だけです。
