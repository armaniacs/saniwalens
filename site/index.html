A lens onto your coding-agent usage

saniwalens reads your agent session transcripts and live configuration, extracts them into a local SQLite store, and shows where time, tokens, and effort are being wasted ― and how to fix it: unused or heavy config, recurring tool failures, where the work gets stuck, and the cost picture behind it all.

Nothing is sent anywhere; the store is a local file. Analysis is read-only and incremental. Full detail lives in the design specs and the docs page.

Install / build

Start with the guided tour

Not sure where to begin? Run saniwalens with no arguments (or saniwalens tui) and answer what it asks:

  1. Which harness to use (claude / opencode / kilocode; skipped with --harness).
  2. What to look at (doctor / waste / failures).
  3. Which scope (global / project / project:<slug>).
  4. It shows the equivalent command before running it, so you can reproduce the same run later.
  5. After the report, it offers to run optimize for that harness and scope right there.
  6. Finally, it asks whether to save the harness to config.toml.

Once you know the flow, call the commands directly:

Every read command refreshes the store automatically (unchanged transcripts are skipped) and prints a freshness line on stderr; pass --frozen to read the store exactly as it is. Add --format markdown to paste into a PR, or --format json for machine-readable output.

Supported harnesses

One harness per run, selected with --harness. The default stays claude, so every existing invocation keeps working byte-identically. Each harness keeps its own store, so findings stay per harness, never mixed.

Per-harness transcripts, config catalog, and store
--harness Agent Transcripts Config catalog
claude (default) Claude Code ~/.claude/projects skills, rules, agents, MCP servers, CLAUDE.md
opencode opencode opencode database commands, agents, AGENTS.md
kilocode Kilo Code editor globalStorage task files commands, agents, skills, AGENTS.md
