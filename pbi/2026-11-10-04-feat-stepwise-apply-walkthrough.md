# PBI: 段階適用ウォークスルー (提案項目単位の予定diff承認)

## ユーザーストーリー
`--apply` で適用する人として、提案を1項目ずつ予定diff・解説つきで確認し、適用/スキップ/中止を選びたい。なぜなら一括承認では何が変わるか分からないまま適用が進むからだ。

## ビジネス価値
- 適用の中身が1項目ずつ可視化され、怖さがなくなる
- スキップ/中止の意思が残り、包括指示による黙認適用を防ぐ
- 測定方法: 全項目に明示の選択記録が残り、未選択の適用がゼロであること
- 設計書: `docs/exploration/2026-11-10-stepwise-apply-design.md` (承認済み)

## BDD受け入れシナリオ

Scenario: 1項目ずつ予定diff承認で進む
  Given 適用プランに複数項目がある
  When  対話適用セッションが始まる
  Then  各項目でバックアップ→予定diff→解説→選択の順に進む
  And   選択なしに次の項目へ進まない

Scenario: スキップと中止が効く
  Given 項目の選択肢が示されている
  When  n と答える
  Then  その項目は適用されず次へ進む
  When  q と答える
  Then  未処理項目の一覧と未適用宣言で終わる

Scenario: 包括指示では黙って適用しない
  Given 未選択の項目が残っている
  When  「残り全部やって」と指示が来る
  Then  未選択の項目は適用されない
  And   1項目ずつの選択が必要な旨が示される

## 技術的考慮事項
- 依存関係: `--apply` ハンドオフと適用手順の安全規格 (`feature/optimize-apply-handoff` 作業ツリー) が前提。単一承認の文言を項目別に更新するため、安全規格 PBI (`pbi/2026-11-10-01-feat-apply-safety-procedure.md`) との差分に注意する
- 指示文は純粋関数に寄せ、起動経路のテストと分離する
- 機械検証ゲートと CLI 駆動ウィザードは非目標 (設計書に記録済み)

## 実装者向け注記

### 現状コードの確認
```bash
grep -n "apply_prompt\|Ask once\|single gate" src/core/optimize.rs | head -n 20
```

### 実装手順
1. 現行 `apply_prompt` の単一承認テストを Red で破る (項目別手順の存在確認)
2. 厳密ステージ (5手順) と `y`/`n`/`q` 定義を追記して Green にする
3. 包括指示拒否と結果サマリ区別を追加し、関連テストを Green にする
4. spec を同一変更で更新する

### 落とし穴
- 既存の単一承認テストと矛盾させない。更新する場合は理由をテストコメントに残す
- 実 transcripts / 実 config をテストに使わない。fixture は合成のみ
- `q` の扱いは「全体打ち切り」で統一し、ガイドの `q` (終了) と混同しないよう文脈を文言に入れる
