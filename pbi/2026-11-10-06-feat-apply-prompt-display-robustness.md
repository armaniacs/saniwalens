# PBI: 適用プロンプトの表示堅牢化 (短い選択肢＋崩れ時の戻し方)

## ユーザーストーリー
対話適用セッションを使う人として、opencode TUI 上で選択肢が読める形で出てほしいし、
崩れても戻し方が分かってほしい。なぜなら実機で option 説明文が1語1行の縦長表示に崩れたからだ。

## ビジネス価値
- 崩れた表示では y/n の判断ができない。適用体験の入口が壊れているのと同義
- 測定方法: 長い項目名でも選択肢行が短く収まり、戻し方の案内が文面にあること

## 背景 (実機観察 2026-11-10)
- opencode TUI の Questions レンダラが option 説明文を極狭幅で折り返した
  (例: `Replace AGENTS.md L189-219 with the 3-line summary ...` が1語1行化)
- 崩し自体は TUI 側の描画であり saniwalens の制御外。こちらでできるのは文面の形と案内

## BDD受け入れシナリオ

Scenario: 選択肢ラベルは短い
  Given 適用項目に長いファイルパスや説明が含まれる
  When  対話プロンプトが組み立てられる
  Then  y/n/q の選択肢行は短い定型文に収まっている
  And   詳細 (ファイル・行番号・要旨) は選択肢の前の本文側にある

Scenario: 崩れた時の戻し方が分かる
  Given 対話適用セッションが始まっている
  When  プロンプトを読む
  Then  表示が崩れた場合の戻し方 (端末のリサイズ/再描画など実在する操作) が一行で案内されている

## 受け入れ基準
- [ ] 選択肢ラベルの長さ上限が決まっている (上限値は実装者が提案しレビューで確定)
- [ ] 詳細情報は選択肢行の外 (本文側) にあることがテストで固定されている
- [ ] 戻し方の案内行があり、記載の操作が実在確認済みである (未確認のキー名を書かないこと。確認は本 PBI 内のスパイク扱いでよい)
- [ ] `cargo test` と `cargo clippy --all-targets -- -D warnings` が green
- [ ] `docs/specs/cli.md` の該当箇所が同一変更で更新されている (文言規格の変更点のみ)

## テスト戦略 (t_wadaスタイル)

### E2Eテスト
- TUI 描画自体は CI で検証不能のため対象外とし、コメントで明示する

### 統合テスト
- プロンプト組み立てテスト (選択肢行の短さ、案内行の存在)

### 単体テスト
- ラベル長の境界値、詳細分離のピン止め

## 見積もり
2 (要チームでの見積もり。内訳目安: ラベル短縮 1、案内行＋確認 1)

## 技術的考慮事項
- 依存関係: `apply_prompt` (段階適用ウォークスルー作業ツリー) が前提
- TUI の描画バグ自体は追わない。文面側でできる緩和に限定する
- 戻し操作のキー名は推測で書かず、ドキュメント確認か実機確認を必須とする

## 実装者向け注記

### 現状コードの確認
```bash
grep -n "y.*apply\|skip\|quit" src/core/optimize.rs | head -n 20
```

### 落とし穴
- 短縮で情報が落ちないこと (削るのは選択肢行であり、本文のファイル・行番号・要旨は残す)
- 実 transcripts / 実 config をテストに使わない。fixture は合成のみ
